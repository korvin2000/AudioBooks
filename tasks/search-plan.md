# Поиск: итоговая концепция, план и статус

1 ноября 2026. Основа — `search-refactoring.md` (далее «спец.»), дополнение — `search-optimization.md` (Codex).
План сведён с тремя независимыми взглядами Fable 5.1 (слушатель/UX, движок, поставка), синтезом Fable и
рецензией Opus по коду. Решения владельца §14 спец. сохранены; отличия названы в §2.

## 1. Концепция

**Для слушателя.** Ввёл запрос — и сразу видно, что с каждым сайтом: чип с иконкой и числом (ищет · ✓ 12 ·
«0» · ⏱ нет ответа · ✕ ошибка · замок), полоска «ответили 7 из 13», сводка словами. Одна книга с пяти сайтов —
одна карточка «5 сайтов», с чтецами и числом озвучек; тап открывает лучшую запись или даёт выбрать чтеца и сайт.
Сверху — то, что совпало лучше всего (по названию, автору, циклу, чтецу), с подписью «совпал чтец». Порядок
меняется одним меню (соответствие, как пришло, название, автор, чтец, короткие/длинные, порядок сайта).
Кнопка-воронка ограничивает поиск полями (Название, Автор, Чтец, Цикл, можно несколько): сайты по-прежнему
ищут текстом, а приложение само проверяет, где именно нашлись слова. Упавший сайт повторяется один, без
перезапуска остальных; «Остановить» прекращает ожидание. Последний поиск сохраняется: повторный вход, возврат
после чипа автора, смерть процесса — результаты показываются сразу, «Результаты от 14:20 · Обновить».

**Для кода.** Сетевой каркас (`SearchSession`, `SiteHttp`, адаптеры) сохранён и расширен операциями на один
источник; вся логика экрана — чистая функция `SearchUi.reduce(Input) → State`, проверяемая на JVM; пост-обработка
(`TextNorm`, `StringSim`, `SearchMatcher`, `SearchGrouper`, `SearchOrder`) — чистые классы без Android.
Презентер — клей: собирает факты, раз в 300 мс отдаёт их редьюсеру вне главного потока, Activity рисует одно
состояние. Каталог и избранное не затронуты (адаптер карточки получил только новый метод `submit`).

## 2. Решения и отличия от спец.

| Вопрос | Решение | Почему |
|---|---|---|
| Логика экрана | Чистый `SearchUi.reduce`; тексты выбирает Activity по enum + числам | Презентер требует Context/Moxy, Robolectric в проекте нет (Fable, поставка D1) |
| Ключ состояния источника | `SearchSession.State` по `Source.name()`; `Provider` резолвит презентер | Сессия общая для книг и людей, тесты на строковых источниках |
| Повтор регистра | Сразу после пустого ответа этого сайта, один раз (не после барьера всех) | Срезает худшее время с ~90 до ~45 с; спец. переносила на этап 5 |
| Догрузка/повтор | `loadNext(source)`, `retry(source)`, `loadNext()` не ждёт занятых | W15: медленный сайт больше не держит остальных |
| Сопоставление слов | Венгерский алгоритм на ≤ 12 × ≤ 96, качество 1 / 0.9 / 0.8 / 0.65, числа только точно | Нормативно A.2; жадный выбор теряет пары (B26) |
| Отчество | Отбрасывается одно и только в имени из 3+ слов (середина или конец) | Иначе «Генрик Сенкевич», «Абрамович» теряют фамилию (уточнение A.1) |
| Группа без автора | Присоединяется только к единственной группе того же названия | Codex §7: не мост между авторами |
| Нечёткое слияние | Включено: совместимые авторы (включение множеств) + Dice ≥ 0.92 + равные числа | Корпус B21–B25, B12, B13, B17, B23 зелёный (тесты) |
| Идентичность группы | id = URL её карточки; показанный id сохраняется при слиянии | DiffUtil не прыгает, фокус держится |
| Список | `BooksListAddapter.submit()` с DiffUtil по URL; статусы прогресса — только для новых книг; обновление статусов payload-ом | W18 без нового адаптера; контракт каталога не меняется |
| Карточка группы | Та же разметка карточки; «5 сайтов» вместо названия сайта, чтецы «А, Б +1», «3 озвучки», причина совпадения | Высота карточки и сетка планшета/TV не ломаются |
| Выбор озвучки | Диалог «чтец · длительность · сайт · издание» | §14 п.3; лист с проверкой доступности — следующий шаг |
| Область | Диалог с галочками + «Везде»; смена области — ноль HTTP; карточки без нужного поля — в конце с пометкой; несовпавшие — скрыты со счётчиком и кнопкой «Искать везде» | PopupMenu закрывается после каждого тапа (Fable UX U-01); §5.2 «UNKNOWN не выбрасывается» |
| % соответствия | Пункт меню «Показывать % соответствия», выключен; по умолчанию — причина словами | Просьба владельца + §6.2 (это ключ сортировки, не вероятность) |
| Умолчания | Соответствие + группировка включены; «Как пришло» и «Группировать» — в меню | Владелец просил сортировку и дедупликацию сейчас; §14 п.10 разносил это по выпускам — откат одним пунктом меню |
| Снимок | Память процесса + `noBackupFilesDir/search/last.json`, Gson, запись `tmp → rename` одним писателем; 3 дня; ≤ 1500 карточек, при усечении у источника снимается продолжение | §8; JVM-тест; не уходит в облачный бэкап (рецензия) |
| Тот же запрос | Моложе 10 мин — снимок без запросов; «Обновить» — заново | §8.3 |
| Прогресс | Determinate «ответили/всего», без анимаций | §14 п.2 (рецензия отклонила indeterminate) |
| Длительности | `ListingFilters.durationMinutes` (−1 = неизвестно), без второго парсера | Рецензия: «Durations» дублировал бы семантику |

Независимая рецензия изменений (4 угла, каждая находка проверена скептиком) подтвердила 13 дефектов — все
исправлены и закреплены тестами: обложка под родительским контролем (пометки группы больше не подменяют жанр),
римские номера томов и номер части в скобке издания не склеиваются, безавторная карточка присоединяется после
слияния написаний автора, чип не показывает «0» после пустой следующей страницы, снимок хранит запрос каждого
источника (вариант регистра), чипы авторов/циклов и честное время получения, конвейер экрана не копит отставание,
отметки прогресса/скачанного у группы — лучшие среди её карточек и обновляются при возврате на экран, после смерти
процесса показывается свой запрос, а не чужой снимок, остановленные сайты не перезапускаются прокруткой.

APK — `test-apk/app-release-search-rework.apk`. На устройстве не проверялось (по правилам `CLAUDE.md` — только по
просьбе владельца, одной фазой).

   спец.; каталог и избранное выглядят как раньше (адаптер карточки общий).
2. **«Долго отвечает» и предел ожидания.** В `Input` — монотонное время и `expectedMs`; таймер презентера
   пересчитывает экран на 8 с и 20 с («Остановить ожидание»); `State` получает `startedAt`. Тест на `TestScheduler`.
3. **`RATE_LIMITED` и `Retry-After`** (W36): `ProviderPage` с кодом и задержкой, один помощник `throwForStatus` в

4. **Кеш ответов + ABMP3 один URL** (§7.5): кешировать тело ответа (не общий `Document` — Jsoup не потокобезопасен),

## 4. Риски

| Риск | Снижение |
|---|---|
| Ложное слияние разных книг | Корпус B в тестах; слияние только при совместимых авторах и равных числах; «Группировать одинаковые» в меню — откат |
| Общий адаптер карточки | Изменения аддитивны (`submit`, подписи по URL); `setItem` каталога прежний; payload вместо `notifyDataSetChanged` для статусов |
| R8 и Gson | keep-правила для `SearchSnapshot*` в `proguard-rules.pro`; release-сборка |
| TV-фокус на чипах, созданных в коде | `focusable` в стиле; D-pad вниз из тулбара — на выбранный чип; проверить на устройстве |
| Отмена логическая | «Остановить»/«Назад» не рвут HTTP до T09: поток `io` занят до таймаута сайта (10–40 с) |
| Без замера | Регистр повторяется у всех, лимиты прежние; оптимизации, требующие чисел, не трогались |
