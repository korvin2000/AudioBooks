# Облачная синхронизация: настройка и устройство

Настройки → «Резервное копирование» → «Облачная синхронизация»: Google Диск или Яндекс Диск. Синхронизируются избранные
книги, история (со временем открытия), избранные авторы и чтецы, позиции прослушивания и пользовательские настройки
(внешний вид, тулбар книги, воспроизведение, скорость, эквалайзер, источники и их порядок, сортировка избранного,
стартовый экран). Не синхронизируются скачанные книги и список глав, пути, прокси и маршруты, cookies, PIN
родительского контроля, служебные кэши.

## Модуль

Весь код — пакет `app/src/main/java/com/fanok/audiobooks/sync/`; приложение о нём знает в двух местах:
`App.onCreate` → `CloudSync.install(this)` и пункт `preferences.xml` с `android:fragment=…sync.SyncSettingsFragment`
(тест `SyncBoundaryTest` следит, чтобы других ссылок не появилось). Модуль пользуется возможностями приложения, которые
о нём не знают: `MediaPlayerService.setCheckpointListener`, `BooksDBModel.ACTION_CHANGED`, `FavoritePeople.update`,
время в `Checkpoint`.

| Класс | Роль |
|---|---|
| `CloudSync` | фасад: `install`, когда синхронизировать, подключение и статус, реестр облаков `SERVICES` |
| `CloudService` | облако как фабрика: id, название, доступно ли, вход (`signIn`), файл аккаунта (`open` → `Cloud`) |
| `Cloud`, `CloudAccount` | транспорт файла синхронизации; аккаунт (имя для статуса, токен) |
| `GoogleDrive`, `YandexDisk` | облака: транспорт и вложенный `Service` с входом |
| `CodeDialog` | ввод кода со страницы входа (переживает пересоздание экрана) |
| `SyncRun` | одна синхронизация: облако, база, слияние, применение, загрузка |
| `DeviceState` | книги, история, люди и позиции устройства: чтение и применение |
| `SyncedSettings` | синхронизируемые настройки: белый список, типы, проверка |
| `Snapshot` | формат файла и трёхстороннее слияние |
| `SyncSettingsFragment` | экран «Облачная синхронизация» (`res/xml/sync_preferences.xml`) |

**Новое облако**: класс, реализующий `Cloud` (чтение/запись файла и тег версии), с вложенным `Service implements
CloudService` (id, название, `available`, `signIn`, `open`), строка в `CloudSync.SERVICES`, название в
`strings_sync.xml`. **Убрать облако**: удалить класс и строку; у пользователей, подключивших его, синхронизация
считается выключенной. **Убрать модуль**: удалить пакет `sync`, строку в `App`, пункт в `preferences.xml`,
`strings_sync.xml`, `sync_preferences.xml`, зависимость `play-services-auth`, `YANDEX_CLIENT_ID` и keep-правила `sync`.

Проект и решения: `tasks/cloud-sync.md`.

## Google Диск — разовая настройка владельцем

В коде идентификаторов нет: Google узнаёт приложение по имени пакета и SHA-1 ключа подписи.

1. [Google Cloud Console](https://console.cloud.google.com/) → создать **один** проект. Он владеет скрытой папкой
   приложения в Диске пользователей; новый проект её не увидит, менять его потом нельзя.
2. APIs & Services → Library → **Google Drive API** → Enable.
3. Google Auth Platform → **Branding**: название приложения, e-mail поддержки и разработчика.
4. **Audience**: External. Для проверки до релиза — Testing и тестовые пользователи (до 100). Перед релизом —
   **Publish app → In production**. Для `drive.appdata` проверка Google не требуется: область «не чувствительная».
5. **Data Access** → Add scopes → `https://www.googleapis.com/auth/drive.appdata`.
6. **Clients → Create client → Android**, пакет `com.fanok.books`; по клиенту на каждый SHA-1:
   - ключ релиза: `keytool -list -v -keystore <файл из keystore.properties> -alias <alias>`;
   - если приложение в Google Play с Play App Signing — SHA-1 ключа подписи из Play Console (App integrity);
   - debug: `keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore -alias androiddebugkey -storepass android`.

Пункт «Google Диск» показывается только при наличии Google Play services.

Ошибки: «ApiException 10» при подключении — пакет/SHA-1 не зарегистрированы или клиент в другом проекте;
`Google Drive HTTP 403 … has not been used / is disabled` — не включён Drive API; «Доступ заблокирован» на экране
согласия — приложение в статусе Testing, а пользователь не в списке тестовых.

## Яндекс Диск — разовая настройка владельцем

WebDAV не подходит: с 22.06.2026 он доступен только подписчикам Яндекс 360. Используется REST API Диска с OAuth.

1. Войти любым Яндекс ID на [oauth.yandex.ru](https://oauth.yandex.ru/) → «Создать приложение» →
   «Для авторизации пользователей».
2. Платформа «Веб-сервисы», Redirect URI: `https://oauth.yandex.ru/verification_code`.
3. Доступы: «Яндекс Диск REST API» → **«Доступ к папке приложения на Диске»** (`cloud_api:disk.app_folder`).
   Другие права не нужны.
4. Скопировать **ClientID** в `gradle.properties`: `YANDEX_CLIENT_ID=<ClientID>` (это не секрет: вход идёт по PKCE,
   client secret не используется). Можно передать и как `-PYANDEX_CLIENT_ID=…` или в `~/.gradle/gradle.properties`.
   Пока значение пустое, пункт «Яндекс Диск» скрыт.

Вход у пользователя: приложение открывает в браузере страницу Яндекса, пользователь входит и разрешает доступ, страница
показывает 7-значный код, пользователь вводит его в диалоге приложения. Файл лежит в «Приложения/<имя приложения>»
на Диске пользователя. Токен действует около года; когда истечёт, статус попросит войти снова.

## Что видит пользователь

- «Облачная синхронизация»: Выключена / Google Диск / Яндекс Диск. Выбор запускает вход; первая синхронизация
  объединяет данные устройства и облака, ничего не удаляя.
- «Синхронизировать сейчас»: в подписи — аккаунт и время последней синхронизации или текст ошибки.
- Автоматически: при открытии приложения, при уходе в фон, через ~30 с после паузы и раз в ~5 минут во время
  прослушивания. Без сети синхронизация пропускается.
- Удаление из избранного или истории на одном устройстве удаляет и на остальных.
- Позиция: если книга на этом устройстве стоит на паузе, а на другом её прослушали дальше, кнопка Play продолжит
  с нового места. Из двух позиций, изменённых на разных устройствах, побеждает более поздняя.

## Устройство

- Файл `audiobooks-sync.json.gz` (Google: скрытая `appDataFolder`; Яндекс: `app:/`) — JSON в gzip: `v` (версия
  формата), `seq` (векторные часы записей по устройствам), `books` (метаданные книг, без аннотации), `fav`, `hist`
  (url → время открытия), `people`, `pos` (url → глава, мс, время, название главы), `prefs` (настройки текстом).
  Неизвестные поля новой версии формата сохраняются при перезаписи; файл с большей версией приложение не перезаписывает.
- Слияние трёхстороннее: с локальной копией последнего согласованного состояния (`noBackupFilesDir/sync-base.json.gz`,
  вне Auto Backup). Изменённое с одной стороны берётся оттуда, включая удаление; с двух — правка сильнее удаления,
  у истории и позиций — более позднее время, у настроек — облако. Если облачный файл не потомок локальной базы (удалён,
  другой аккаунт, параллельная запись), слияние — объединение: удалённое может вернуться, добавленное не теряется.
- Перед записью проверяется версия файла в облаке: изменился — слияние заново.
- Запись, которую это устройство применить не может (книга без названия, значение настройки, неизвестное этой версии,
  позиция книги, которой здесь нет ни в списках, ни в прослушанных), остаётся в облаке и не считается удалённой.
  Битая запись в файле пропускается одна, остальные читаются.
- Авторы и чтецы синхронизируются как «есть/нет»; ссылки на их страницы — только при добавлении на устройство.
- «Выключена» отключает только это устройство: доступ Google не отзывается (иначе он пропал бы и на других
  устройствах), файл в облаке остаётся. Повторный выбор того же облака после ошибки — вход заново.
- Яндекс иногда принимает файл с ответом 202 и переносит его на Диск позже: приложение ждёт до 10 с, пока md5 файла
  на Диске не совпадёт с записанным.
- Сеть: отдельный OkHttp-клиент напрямую, без прокси приложения для сайтов (токены не идут через них).
- `Checkpoint` хранит время позиции (формат `2|глава|мс|время|url`, старый `1|…` читается). После установки более
  старой версии приложения позиции не читаются — как и БД, откат не поддерживается.
- История сортируется по времени открытия (`HistoryDao`), а не по порядку записей.
